# v2.1.0 - First Stable Release of the V2 Series

> Stable release. Published from `main`; this release updates the stable aliases
> (`latest`, `main`, `2.1`, `2`, and the exact tags) and the Docker Hub
> description. V2 remains an early major line.

## Summary

v2.1.0 is the first stable release since v2.0.0. It consolidates the complete
development series v2.0.1 through v2.0.15 into one supported release: the
resource-aware upload pipeline, the server-side image recipe, the localized
web application, and the documented Docker deployment. No development-only
behaviour is included; every change was already published and verified on the
`dev` channel.

## Highlights

### Upload pipeline and image policy

- Browser processing preflight and durable upload recovery, including resumable
  sessions and the client polling deadline.
- The fixed image policy (variants, pixel and byte limits, accepted source
  formats) lives in a server-side recipe file with a generated schema SQL
  snapshot for production provisioning.
- The recipe endpoint returns advisory client hints, and the frontend follows
  the server's upload policy with bounded fallbacks.
- The remaining V1 compatibility limits are configurable, and startup
  performance configuration is bounded.

### Web application

- A bounded client crash reporting endpoint records render crashes, uncaught
  errors, and unhandled rejections in the server log without database state.
- Error messages are English on the server, and the frontend maps error codes
  to localized text in all three interface languages.

### Documentation and localization

- English-first trilingual documentation with a hardened GitBook verifier,
  third-party attribution, and a public third-party software page.
- Audit follow-ups: the rollback integration test runs in CI, the development
  imgproxy container reads host-owned data, and the bounded V1 dynamic
  rejection is documented.

### Deployment and operations

- Fail-fast database bootstrap with advisory locking and immutable migration
  checksums; supervised worker shutdown; explicit configuration boundaries.
- The production deployment uses a small directory layout (Compose file,
  `.env`, and `config/image-recipe.json`), and the recipe is mounted read-only
  over the recipe baked into the image.

## Verification

At release time: the backend standard suite and the scoped MySQL integration
tests pass, the frontend passes lint, build, and 22 test files with 164 tests,
the Python requirements lock verifies, and the GitBook documentation verifier
passes for all 39 pages in each locale. The local stress validation recorded
stable behaviour under the documented concurrency bounds and bounded rejection
for saturated dynamic transforms.

## Installation

Stable images are pulled with an exact version:

```bash
docker pull jaykserks/summerain:2.1.0
```

Equivalent exact tag:

```text
jaykserks/summerain:v2.1.0
```

Stable aliases (`latest`, `main`, `2.1`, and `2`), the commit tag, and the OCI
multi-platform index are also available. Pin an exact tag or OCI index digest
in production.

## Upgrade Notes

- Upgrade from v2.0.0 (the previous stable release): startup applies the
  additive migrations automatically. Back up MySQL and the image volume first.
- Diff `.env` against `backend/.env.example`; the development series added new
  configuration variables and the recipe file.
- The deployment Compose file mounts `config/image-recipe.json` read-only and
  refuses to start when it is missing; create it beside the Compose file.
- The development channel remains `dev`; stable releases are published only
  from `main`.

## Known Limitations

- V2 remains an early major line; behaviour may still change in later minors.
- Animated images and GIF are not supported; V2 persists fixed variants only.
- Existing V1 images are not converted automatically, and historical R2
  migration is delegated to a separate tool.
- CI runs the scoped MySQL integration subset; the full integration suite
  requires the documented DSN variables.
