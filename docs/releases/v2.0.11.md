# v2.0.11 - Client Crash Reporting

> Development prerelease. This release is published from `dev`, may receive
> rapid follow-up changes, and is not selected by the default `latest` image.

## Summary

v2.0.11 replaces the last console writes in the frontend with a bounded,
structured crash report that the server records in its log. React render
crashes, uncaught errors, and unhandled promise rejections are now reported
once, deduplicated, and truncated instead of being lost in a browser console.

The endpoint keeps no database state, is rate limited per IP, and never receives
query strings, cookies, or tokens. The frontend linter now enforces the
repository's console ban, which previously had three exceptions.

## Changes

### Backend endpoint

- Added `POST /api/v1/public/client-errors`, which accepts one bounded JSON
  report and writes a single `[client-error]` log line carrying the request ID.
- Report kinds are limited to `boundary`, `error`, and `unhandledrejection`; an
  empty message or an unknown kind is rejected with `3000`.
- Fields are truncated server-side: message 300 bytes, stack and component stack
  2000 bytes, source and path 200 bytes, user agent 200 bytes.
- The request body is capped at 8 KiB (`3002` when exceeded), and each IP may
  send at most 20 reports per minute; further reports return the new `2091`
  (429) with `Retry-After: 60`. A Redis failure keeps the existing fail-closed
  behavior.
- The service never logs IP addresses, cookies, or tokens.

### Frontend reporting

- Added `lib/crash-report.ts`: truncation that mirrors the server, path-only
  reporting (query strings and fragments are stripped so private image tokens
  cannot leak), a five-second fingerprint deduplication window, and a budget of
  three reports per page per minute.
- Added `lib/global-crash-handlers.ts`, installed once at boot, to report
  uncaught errors and unhandled promise rejections that never reach a React
  error boundary.
- `ErrorBoundary` now reports through `reportClientCrash` instead of
  `console.error`; the DOM-mutation self-healing retry is unchanged.
- Removed two debug `console.error` calls from the image list delete flow.
- Added the `no-console: error` ESLint rule, with an explicit override for
  tests, so the console ban stays enforced.

## Installation

Development images must be pulled explicitly:

```bash
docker pull jaykserks/summerain:dev-v2.0.11
```

Equivalent exact development tag:

```text
jaykserks/summerain:dev-2.0.11
```

The moving `dev` tag also points to the newest successful development build.
`latest`, `main`, and stable semantic-version aliases are not changed by this
release.

No database migration or API migration is required when upgrading from v2.0.10.

## Known Limitations

- Reports are written to the server log only; the server does not aggregate or
  alert on them.
- The endpoint is public by design, so a hostile client can call it; the body
  cap and the per-IP rate limit bound the impact, and a report never contains
  authentication input.
- Animated image support remains planned for a later release.
