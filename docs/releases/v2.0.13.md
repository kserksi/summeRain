# v2.0.13 - English Error Messages and Client-Side Localization

> Development prerelease. This release is published from `dev`, may receive
> rapid follow-up changes, and is not selected by the default `latest` image.

## Summary

v2.0.13 makes every backend error message, notification, and comment English,
and moves user-visible error text to the frontend's `code`-to-locale map. The
frontend falls back to the server message only when a code has no localized
entry. Chinese text no longer appears in English or Japanese interfaces.

No API contract or database schema changes in this release.

## Changes

### Backend

- Translated every `errcode` message, inline error string, notification title
  and body, and source comment to English. Error codes and HTTP statuses are
  unchanged.
- Notifications that carry values now store them in structured metadata
  (`percent` for the quota warning, `quota` for the quota update) so clients
  can localize them with interpolation.

### Frontend

- Added `apiErrorMessage`, which resolves `ApiError` codes through the
  `errors.<code>` locale entries and falls back to the server message when a
  code is unmapped.
- Applied the helper to the password-change, image-deletion, and upload
  failure surfaces; notifications now render from a `type`-based locale
  template with metadata interpolation, and the admin language selector uses
  locale labels.
- Added 23 error-code entries, six notification templates, four upload
  recovery fallbacks, and language labels to all three locales.
- Translated the remaining Chinese source comments.

### Documentation

- The API reference now documents the English `message` fallback and the
  client-side `code` mapping, with all three languages updated.

## Installation

Development images must be pulled explicitly:

```bash
docker pull jaykserks/summerain:dev-v2.0.13
```

Equivalent exact development tag:

```text
jaykserks/summerain:dev-2.0.13
```

The moving `dev` tag also points to the newest successful development build.
`latest`, `main`, and stable semantic-version aliases are not changed by this
release.

No database migration or API migration is required when upgrading from v2.0.12.

## Known Limitations

- Notifications with an unknown `type` fall back to their stored text, which
  may originate from an older release.
- Upload recovery fallbacks are localized when a failure is recorded; changing
  the interface language later does not retranslate already-persisted
  failures.
- Error codes without a locale entry fall back to the English server message.

## Related Work

This release completes the error-message localization stage of the v2 roadmap.
The backend is now English-only, and the frontend owns user-visible error
wording.
