# v2.0.14 - Docker Deployment Layout and Recipe Override

> Development prerelease. This release is published from `dev`, may receive
> rapid follow-up changes, and is not selected by the default `latest` image.

## Summary

v2.0.14 completes the Docker deployment story. A production host now needs a
deployment directory with the Compose file, `.env`, and an editable
`config/image-recipe.json`; the recipe is bind-mounted read-only over the
recipe baked into the image, and Compose refuses to start when it is missing.
No application code changes in this release.

## Changes

### Compose

- Both `backend/docker-compose.yml` and `backend/docker-compose.deploy.yml`
  mount `./config/image-recipe.json` read-only at `/app/config/image-recipe.json`
  with `create_host_path: false`, so a missing file fails fast instead of
  Docker silently creating a directory.
- Operators can now change variants, limits, or accepted formats by editing the
  deployment copy and restarting, without rebuilding or replacing the image.
- Added `backend/config/image-recipe.json` as the deployment copy of the
  server-side policy file.

### Tests

- `backend/deploy_config_test.go` now asserts the recipe override mount in both
  Compose files and that the deployment copy stays byte-identical to the
  embedded default.

### Documentation

- README and the deployment guide document the deployment directory layout,
  the read-only recipe override, the Compose fail-fast behavior, and how to
  back up the named volumes; the update and rollback commands run from the
  deployment directory, in all three languages.

## Installation

Development images must be pulled explicitly:

```bash
docker pull jaykserks/summerain:dev-v2.0.14
```

Equivalent exact development tag:

```text
jaykserks/summerain:dev-2.0.14
```

The moving `dev` tag also points to the newest successful development build.
`latest`, `main`, and stable semantic-version aliases are not changed by this
release.

No database migration or API migration is required when upgrading from v2.0.13.
Deployments upgrading in place must place `config/image-recipe.json` beside
their Compose file (for a repository checkout, `backend/config/image-recipe.json`)
before the next start, because Compose now refuses to start without it.

## Known Limitations

- Persisted image files remain in the `image_storage` named volume rather than
  a host directory; use the documented backup procedure for volume data.
- Changing the recipe still requires a restart and a `recipe_version` bump.
- Development deployments using the repository checkout need the same
  `config/image-recipe.json` copy beside the Compose file.

## Related Work
