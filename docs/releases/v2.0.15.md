# v2.0.15 - Audit Follow-Ups: Tests, Development Environment, and Documentation

> Development prerelease. This release is published from `dev`, may receive
> rapid follow-up changes, and is not selected by the default `latest` image.

## Summary

v2.0.15 addresses the findings from the local stress audit: the previously
panicking integration test now runs and is part of the scoped CI integration
step, the development imgproxy container can read developer-owned data without
world-readable permissions, and the API and deployment guides describe the
bounded V1 dynamic-transform rejection. No runtime behavior changes.

## Changes

### Tests and CI

- `TestCompleteRollbackRestoresStagingAndCleansPersistentParts` now injects the
  shared test recipe instead of leaving it nil, so the rollback path actually
  executes instead of panicking on a nil recipe.
- The scoped MySQL integration step runs that test alongside the lease-cleanup
  tests, closing the gap where it was never executed by CI.

### Development environment

- `backend/docker-compose.dev-deps.yml` adds the host group
  (`SUMMERAIN_DEV_GID`, default `1000`) to the imgproxy container, so it can
  read originals owned by the developer account under the default
  owner/group-only permissions. Local V1 dynamic transforms now work without
  loosening the data directory to world-readable.

### Documentation

- The API reference and the deployment guide state that the bounded V1 dynamic
  path rejects saturation with `1003` (503) and a `Retry-After` header instead
  of queueing without bound; both translations are updated.

## Verification

- Backend: the full integration suite with `SUMMERAIN_TEST_MYSQL_DSN` set
  passes, including the previously panicking test; the standard suite and the
  CI-scoped integration commands pass.
- Development environment: `docker compose config` validates; with
  owner/group-only permissions on the development data directory, a V1 dynamic
  transform returns 200.
- Frontend `npm run lint`, `tsc -b`, and Vitest: 22 test files, 164 tests
  passed.
- Python requirements lock verification and GitBook documentation verification:
  passed for all 38 pages in each locale.

## Installation

Development images must be pulled explicitly:

```bash
docker pull jaykserks/summerain:dev-v2.0.15
```

Equivalent exact development tag:

```text
jaykserks/summerain:dev-2.0.15
```

The moving `dev` tag also points to the newest successful development build.
`latest`, `main`, and stable semantic-version aliases are not changed by this
release.

No database migration or API migration is required when upgrading from v2.0.14.

## Known Limitations

- CI still runs only the scoped MySQL integration subset; the full integration
  suite requires the documented DSN variables.
- The development group default assumes uid/gid `1000`; set
  `SUMMERAIN_DEV_GID` for other host setups.
- Dynamic transforms without a format extension continue to return the
  original image by design.
