# v2.0.9 - Recipe Client Hints

> Development prerelease. This release is published from `dev`, may receive
> rapid follow-up changes, and is not selected by the default `latest` image.

## Summary

v2.0.9 extends `GET /api/v1/uploads/recipe` with advisory client hints so the
browser can size its own upload pipeline from server policy instead of
hardcoded values. Every existing field keeps its name, type, and meaning, and
the new keys are additive, so clients built for older releases parse the
response unchanged.

The server still validates every request independently: the hints never widen
what the server accepts.

## Changes

### Recipe client hints

- `max_source_bytes` (default `15728640`, range 1 MiB to 64 MiB from
  `V2_MAX_SOURCE_BYTES`) is the source file size the browser accepts before
  processing.
- `client_pipeline_concurrency` (default `2`, range 1 to 8 from
  `CLIENT_UPLOAD_PIPELINE_CONCURRENCY`) is the advisory browser upload-pipeline
  concurrency.
- `client_active_session_concurrency` (default `4`, from
  `CLIENT_ACTIVE_SESSION_CONCURRENCY`) is the advisory concurrent
  upload-session count; it must not exceed `V2_MAX_ACTIVE_SESSIONS_PER_USER`,
  and a deployment that lowers the server limit must lower this value too.
- `client_max_native_concurrency` (default `2`, range 1 to 4 from
  `CLIENT_MAX_NATIVE_CONCURRENCY`) is the advisory native (Canvas/Pica)
  processor concurrency.
- `supported_source_mime_types` mirrors the recipe's accepted source formats.
- Configuration errors in the four new variables stop startup before MySQL is
  contacted, and the effective values appear in the startup summary log.

### Documentation

- `docs/API.md` documents the new keys and carries a complete recipe response
  example; `docs/USAGE.md` lists the four new variables. Both pages and their
  Simplified Chinese and Japanese mirrors are updated together.

## Installation

Development images must be pulled explicitly:

```bash
docker pull jaykserks/summerain:dev-v2.0.9
```

Equivalent exact development tag:

```text
jaykserks/summerain:dev-2.0.9
```

The moving `dev` tag also points to the newest successful development build.
`latest`, `main`, and stable semantic-version aliases are not changed by this
release.

No database migration or API migration is required when upgrading from v2.0.8.

## Known Limitations

- The hints are advisory; this release does not change the frontend, which
  starts reading them in the later client configuration phase.
- Lowering `V2_MAX_ACTIVE_SESSIONS_PER_USER` below the configured
  `CLIENT_ACTIVE_SESSION_CONCURRENCY` now fails startup instead of silently
  ignoring the mismatch.
- Animated image support remains planned for a later release.
