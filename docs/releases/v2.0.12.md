# v2.0.12 - Documentation Compliance and Third-Party Attribution

> Development prerelease. This release is published from `dev`, may receive
> rapid follow-up changes, and is not selected by the default `latest` image.

## Summary

v2.0.12 makes the English documentation the single consolidated source of
truth, closes its compliance gaps, and re-syncs both translations from the
finalized English. It also adds the third-party attribution page required by
the licensing policy and hardens the GitBook verifier against emoji,
structure drift, and stale version strings.

No server behavior or API contract changes in this release.

## Changes

### Documentation consolidation

- README: removed the duplicated request diagram and the repeated limit and
  pool numbers; capability wording is now version-independent; the release
  notes link points to the GitHub Releases page; archived design records are
  labeled; the technology table links to the attribution page.
- USAGE: unified the Go version wording (1.24+, CI uses 1.26.5); the local
  quick start points to the README; the configuration reference was checked
  against the code and `.env.example` (including `GOMEMLIMIT` being
  Compose-injected); worker names match the manager; the limits table no
  longer carries maintainer source columns; the nginx body limit was corrected
  from 20m to 64m.
- API: removed the obsolete mock-mapping section, sorted the error-code table,
  removed the verification-baseline note, and dropped the generation footer.
- CONTRIBUTING: the Google Go Style Guide is now the declared baseline; the
  frontend checks and documentation-maintenance rules are documented.
- SECURITY: canonical repository URL and a supported-versions note for
  development builds.
- `backend/.env.example`: the image example keeps an exact stable tag, with
  explicit production pinning guidance.

### Third-party attribution

- Added `docs/THIRD-PARTY.md`, listing the adopted libraries, services, and
  toolchains with authors, licenses, and links; expanded `NOTICE` accordingly.
- `libvips` (LGPL-2.1-or-later) and Redis 8 (RSALv2/SSPLv1/AGPLv3) usage is
  documented as unmodified, separately deployed components.

### Translations

- Simplified Chinese and Japanese pages were re-synced from the finalized
  English; removed the remaining emoji and editorial headings from the Chinese
  API page; unified terminology; translated the new attribution page; refreshed
  all three navigations and the translation source hashes.

### Verifier hardening

- `scripts/verify-gitbook-docs.sh` now rejects emoji and stale `v2.0.0`
  references on current pages, and requires translations to match the canonical
  heading, table, and code-fence structure. Archived design records and dated
  release notes are exempt as historical records.

## Installation

Development images must be pulled explicitly:

```bash
docker pull jaykserks/summerain:dev-v2.0.12
```

Equivalent exact development tag:

```text
jaykserks/summerain:dev-2.0.12
```

The moving `dev` tag also points to the newest successful development build.
`latest`, `main`, and stable semantic-version aliases are not changed by this
release.

No database migration or API migration is required when upgrading from v2.0.11.

## Known Limitations

- The documentation describes the latest stable release; `dev` may contain
  unreleased changes until they are published.
- The README release link points to the GitHub Releases page, so it does not
  pin a single version.
- Animated image support remains planned for a later release.

## Related Work

Documentation is now maintained English-first with translations synced from the
