# v2.0.5 - Configuration Boundaries

> Development prerelease. This release is published from `dev`, may receive
> rapid follow-up changes, and is not selected by the default `latest` image.

## Summary

v2.0.5 establishes explicit ownership boundaries between the configuration
sources. Deployment settings stay in the environment, the fixed image recipe
stays on the server, and only administrator-managed business settings remain
writable through the existing configuration API.

The administrator configuration API now validates an explicit allowlist before
opening a database transaction. Unknown keys and deployment or protocol keys are
rejected instead of being persisted into `system_configs`.

This release does not add a database schema version, change an HTTP or upload
API, or change an image-processing recipe.

## Changes

### Administrator configuration allowlist

- Added a single allowlist for administrator-writable system configuration:
  `site_language`, `captcha_provider`, `captcha_site_key`, `captcha_secret`,
  `private_token_ttl_default_ms`, the `watermark_*` keys, and the `r2_*` keys.
- Rejects unknown keys before any database transaction starts.
- Rejects deployment and protocol keys such as `DB_*`, `REDIS_*`, `V1_*`,
  `V2_*`, `IMGPROXY_*`, `MAX_JSON_BODY_BYTES`, and image-recipe keys.
- Rejects an empty configuration key with a parameter error.
- Preserves the existing CAPTCHA, R2, and watermark validation rules.

### Tests

- Covers allowlisted business configuration, rejected deployment and protocol
  keys, and empty-key rejection.

## Installation

Development images must be pulled explicitly:

```bash
docker pull jaykserks/summerain:dev-v2.0.5
```

Equivalent exact development tag:

```text
jaykserks/summerain:dev-2.0.5
```

The moving `dev` tag also points to the newest successful development build.
`latest`, `main`, and stable semantic-version aliases are not changed by this
release.

No database migration or API migration is required when upgrading from v2.0.4.

## Known Limitations

- Only the administrator configuration API is restricted by this allowlist.
  Startup-level environment variables are still read once at process start.
- The complete fixed image recipe remains a server-side concern and is planned
  for a later release.
- Animated image support remains planned for a later release.
