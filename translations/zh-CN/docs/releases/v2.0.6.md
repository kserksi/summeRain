# v2.0.6 - 启动级性能配置

> 开发预发布版本。此版本从 `dev` 分支发布，后续修改可能较为频繁，
> 并且不会被默认的 `latest` 镜像选中。

## 概述

v2.0.6 将需要重启才能生效的后端性能限制迁移到部署环境变量。每个限制只在启动时读取和
校验一次，不能通过管理员 API 修改，不会返回给前端，并在启动日志中以不含凭据的方式输出摘要。

配置错误现在会在连接 MySQL 或 Redis 之前终止进程，因此非法部署会快速失败，
而不是带着意外的资源行为启动。

此版本不新增数据库结构版本，不改变 HTTP 或上传 API，也不改变图片处理配方。

## 变更

### 启动级限制

- `MAX_JSON_BODY_BYTES` 限制普通 JSON 请求体。默认 1048576，范围 1 KiB 到 16 MiB。
- `V2_INIT_MAX_JSON_BYTES` 限制 V2 上传清单。默认 65536，范围 1 KiB 到 1 MiB，
  且不得超过 `MAX_JSON_BODY_BYTES`。
- `V2_BATCH_STATUS_MAX_JSON_BYTES` 限制批量状态查询请求。默认 16384，
  范围 1 KiB 到 256 KiB，且不得超过 `MAX_JSON_BODY_BYTES`。
- `V2_MAX_ACTIVE_SESSIONS_PER_USER` 限制单用户并发的 V2 上传会话。默认 8，范围 1 到 32。
- `V1_DYNAMIC_GENERATION_CONCURRENCY` 决定 V1 动态转换信号量大小。默认 2，范围 1 到 16。
- `V1_DYNAMIC_GENERATION_QUEUE_DEPTH` 决定 V1 等待队列深度。默认 4，范围 0 到 64。
- `V1_BACKGROUND_FORMAT_CONCURRENCY` 决定 V1 后台格式转换 worker 数量。默认 1，范围 1 到 8。

### 接线与可观测性

- V1 动态转换和后台格式信号量在启动时按校验后的配置创建。
- V2 活动会话上限改为按配置执行，不再使用代码常量。
- 全局 JSON 中间件和 V2 上传处理器使用配置的请求体限制。
- 启动日志按配置分组输出非敏感摘要行；凭据、密钥和连接串不会出现在日志中。

### 部署示例

- `backend/.env.example` 记录了所有新增变量，依赖锁校验会断言它们存在。

## 安装

开发镜像必须显式拉取：

```bash
docker pull jaykserks/summerain:dev-v2.0.6
```

等效的精确开发标签：

```text
jaykserks/summerain:dev-2.0.6
```

滚动的 `dev` 标签也会指向最新一次成功的开发构建。此版本不会修改 `latest`、`main`
以及稳定的语义化版本别名。

从 v2.0.5 升级不需要数据库迁移或 API 迁移。
