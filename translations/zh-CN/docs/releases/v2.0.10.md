# v2.0.10 - 前端遵循服务端上传策略

> 开发预发布版本。此版本从 `dev` 分支发布，可能会快速接收后续更改，不会被默认的 `latest` 镜像标签选择。

## 概述

v2.0.10 让浏览器上传流水线读取 v2.0.9 新增的配方客户端提示，而不再依赖构建期常量。
最终并发与源文件体积上限取「服务端提示、设备能力、前端安全上限」三者的最小值：运维人员无需
重新发布前端即可从服务端降低浏览器侧负载，同时性能较弱或内存受限的设备仍保持自身的下限。
未下发这些提示的服务端则完全保持原有行为。

配方版本不再是前端常量：客户端会回传服务端给出的版本，并在版本变化时重新处理已持久化的结果。

## 变更内容

### 生效的上传限制

- `client_pipeline_concurrency` 与 `client_active_session_concurrency` 分别决定上传流水线
  并发和活跃服务端会话闸门，且都不会超过前端上限 2 与 4。
- `client_max_native_concurrency` 会与设备能力（上报核心数的一半，取值 1 到 2）取最小值，
  弱设备不会以超过自身承受能力的 Worker 数处理图片。
- `max_source_bytes` 取代固定的 15 MiB 预检查，并在添加文件时与预检阶段各校验一次，
  因此在配方返回之前加入的文件同样会按服务端策略被拒绝。
- 提示缺失时沿用随客户端发布的默认值，这正是旧版服务端所期望的行为。提示存在但不可用
  （为零、负数、小数或非数字）时回退到上限，并弹出一条列出字段名的告警提示，
  而不是静默忽略配置错误。
- 前端绝不会把限制提高到服务端取值或自身上限之上。

### 动态配方版本

- 移除了原生处理器、WASM Worker、预检、共享类型与配方解析中硬编码的 `2.0.0`。
- 当配方的流水线版本或变体尺寸超出客户端能力时仍会拒绝，且错误现在会带上服务端的
  `recipe_version` 与 `pipeline_version`。
- 服务端配方版本变化后，已持久化的处理结果会被丢弃并重新生成。上传队列恢复、租约与
  重试语义保持不变。

## 安装

必须显式拉取开发镜像：

```bash
docker pull jaykserks/summerain:dev-v2.0.10
```

等效的精确开发标签：

```text
jaykserks/summerain:dev-2.0.10
```

移动的 `dev` 标签也指向最新的成功开发构建。`latest`、`main` 和稳定的语义版本别名
不受此版本影响。

从 v2.0.9 升级不需要数据库迁移或 API 迁移。
