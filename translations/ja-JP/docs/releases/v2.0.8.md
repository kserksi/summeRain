# v2.0.8 - 画像レシピファイルと生成スキーマ SQL

> 開発プレリリース版。このリリースは `dev` から公開され、迅速なフォローアップ変更を受ける可能性があり、デフォルトの `latest` イメージでは選択されません。

## 概要

v2.0.8 は、固定画像ポリシーを Go の定数と環境変数からサーバー側のレシピファイルへ移し、
本番デプロイメント向けに MySQL スキーマを明示的な SQL として書き出す生成器を追加します。

レシピファイルは、バリアントの寸法、ピクセルとサイズの上限、受け付けるソース形式、
そしてブラウザーのアップロードが送信すべき `recipe_version` を担います。コンテナは既定の
レシピを `/app/config/image-recipe.json` に配置し、バイナリーは同じ既定を埋め込みます。
`IMAGE_RECIPE_FILE` と `IMAGE_RECIPE_REQUIRED` が参照先を制御します。ファイルが無い場合は
必須指定でない限り組み込みの既定へフォールバックし、読み取り不能・形式不正・範囲外の値は
MySQL に接続する前に起動を停止させます。

`V2_RECIPE_VERSION`、`V2_MAX_PART_BYTES`、`V2_MAX_PIXELS` は読み込まれなくなりました。
これらの値はレシピファイルへ移してください。既定値は変わらないため、変更していない
デプロイメントは v2.0.7 とまったく同じ動作になります。

## 変更内容

### 画像レシピファイル

- 既定のレシピ `backend/internal/config/image-recipe.json` を追加し、`go:embed` で
  バイナリーに埋め込み、イメージ内の `/app/config/image-recipe.json` へも配置します。
- `IMAGE_RECIPE_FILE`（既定 `/app/config/image-recipe.json`）と
  `IMAGE_RECIPE_REQUIRED`（既定 `false`）を追加しました。
- レシピは `pipeline_version`、`recipe_version`、`max_pixels`、`max_part_bytes`、
  `supported_source_mime_types`、および 4 つの固定バリアント
  （`master`、`gallery`、`admin`、`publish_source`）を宣言します。
- コード側の境界はコードに残します。`pipeline_version` は 2 に固定、ソース MIME 一覧は
  対応する 5 形式の空でない部分集合、`max_pixels` は 1 MP から 100 MP、`max_part_bytes`
  は 1 MiB から 64 MiB、バリアント寸法は 1 から 4096 ピクセル、品質は 1 から 100 の
  範囲に収まる必要があります。レシピはこれらの値を厳しくできるだけで、超えることはできません。
- バリアント検証、ソース MIME の受け入れ、パートサイズとピクセル上限、
  `/api/v1/uploads/recipe` の応答は、コード定数ではなくレシピを参照するようになりました。
  応答の形は変わりません。
- 起動ログには、参照元・バージョン・上限・バリアント概要を含む `image_recipe_*` の
  1 行を出力します。認証情報は決して含まれません。
- レシピは管理者 API の対象外です。レシピ関連のキーは既存の設定許可リストで拒否されます。

### 生成されたスキーマ SQL

- `backend/cmd/schema-migration-gen` と `scripts/generate-sql-migration.sh` を追加しました。
- `bash scripts/generate-sql-migration.sh baseline_schema` は
  `backend/migrations/<UTC タイムスタンプ>_baseline_schema.up.sql` を書き出し、
  その場で検証します。
- 生成は `SUMMERAIN_SCHEMA_DSN` 上に使い捨てデータベースを作成して削除するだけで、
  既存のデータベースには一切触れません。
- 検証では、空のデータベースへファイルを適用し、その後のブートストラップがスキーマを
  変更しないことを要求します。これにより、スナップショットが GORM モデルとすべての
  チェックサム付きマイグレーションに一致することが証明されます。
  `SUMMERAIN_SCHEMA_DSN` を設定すると `go test ./cmd/schema-migration-gen/...` が
  同じ検査を実行します。
- `backend/migrations/20261003_122900_baseline_schema.up.sql`（全 17 テーブル）を
  コミットしました。

### デプロイメント例

- `backend/.env.example` は新しい 2 つの変数を記載し、レシピが引き継いだ 3 つの変数を
  削除しました。依存ロックの検証スクリプトは新しい行の存在を検査します。

## インストール

開発イメージは明示的にプルする必要があります：

```bash
docker pull jaykserks/summerain:dev-v2.0.8
```

同等の正確な開発タグ：

```text
jaykserks/summerain:dev-2.0.8
```

移動する `dev` タグも最新の成功した開発ビルドを指します。`latest`、`main`、および
安定したセマンティックバージョンエイリアスはこのリリースによって変更されません。

v2.0.7 からのアップグレードにデータベース移行や API 移行は不要です。カスタムの
`V2_RECIPE_VERSION`、`V2_MAX_PART_BYTES`、`V2_MAX_PIXELS` を設定していた場合は、
デプロイ前にレシピファイルへ移してください。

## 既知の制限

- 生成される SQL は空のデータベース向けの完全なスキーマスナップショットです。既存の
  データベース向けの増分 `ALTER TABLE` 生成はこのリリースには含まれません。既存の
  データベースは追加型のチェックサム付きランナーで引き続きアップグレードされます。
- レシピは起動時に一度だけ読み込まれます。変更には再起動と `recipe_version` の更新が必要です。
- 後続のクライアント設定フェーズまで、フロントエンドは固定の `recipe_version` を送信します。
  既定のレシピによって両者は同期します。
- アニメーション画像のサポートは今後のリリースで計画されています。
