# v2.0.6 - 起動時のパフォーマンス設定

> 開発プレリリースです。本リリースは `dev` から公開され、短期間で変更が
> 加えられる可能性があります。また、既定の `latest` イメージでは選択されません。

## 概要

v2.0.6 では、再起動が必要なバックエンドのパフォーマンス制限をデプロイ環境変数へ移行します。
各制限は起動時に一度だけ読み込まれて検証され、管理者 API からは変更できず、フロントエンドへ
返されることもありません。起動ログには認証情報を含まない要約だけを出力します。

設定エラーが発生した場合、プロセスは MySQL や Redis へ接続する前に終了します。
そのため、不正なデプロイは予期しないリソース動作で起動せず、早期に失敗します。

本リリースでは、データベーススキーマバージョン、HTTP またはアップロード API、
画像処理レシピを変更しません。

## 変更点

### 起動時のみ有効な制限

- `MAX_JSON_BODY_BYTES` は通常の JSON リクエスト本文を制限します。既定値は 1048576、
  範囲は 1 KiB から 16 MiB です。
- `V2_INIT_MAX_JSON_BYTES` は V2 アップロードマニフェストを制限します。既定値は 65536、
  範囲は 1 KiB から 1 MiB で、`MAX_JSON_BODY_BYTES` を超えてはいけません。
- `V2_BATCH_STATUS_MAX_JSON_BYTES` は一括ステータス要求を制限します。既定値は 16384、
  範囲は 1 KiB から 256 KiB で、`MAX_JSON_BODY_BYTES` を超えてはいけません。
- `V2_MAX_ACTIVE_SESSIONS_PER_USER` はユーザーごとの同時 V2 アップロードセッションを
  制限します。既定値は 8、範囲は 1 から 32 です。
- `V1_DYNAMIC_GENERATION_CONCURRENCY` は V1 動的変換セマフォの大きさを決めます。
  既定値は 2、範囲は 1 から 16 です。
- `V1_DYNAMIC_GENERATION_QUEUE_DEPTH` は V1 待機キューの深さを決めます。既定値は 4、
  範囲は 0 から 64 です。
- `V1_BACKGROUND_FORMAT_CONCURRENCY` は V1 バックグラウンド変換 worker の数を決めます。
  既定値は 1、範囲は 1 から 8 です。

### 配線と可観測性

- V1 の動的変換セマフォとバックグラウンド変換セマフォは、検証済みの設定から
  起動時に作成されます。
- V2 の同時セッション上限は、コード定数ではなく設定から適用されます。
- グローバル JSON ミドルウェアと V2 アップロードハンドラーは、設定された本文制限を
  使用します。
- 起動ログは設定グループごとに 1 行の非機密の要約を出力します。認証情報、秘密鍵、
  接続文字列はログに出力されません。

## インストール

開発イメージは明示的に pull する必要があります。

```bash
docker pull jaykserks/summerain:dev-v2.0.6
```

同等の正確な開発タグ:

```text
jaykserks/summerain:dev-2.0.6
```

移動可能な `dev` タグも最新の成功した開発ビルドを指します。本リリースでは
`latest`、`main`、安定版セマンティックバージョンのエイリアスは変更されません。

v2.0.5 からのアップグレードにデータベースまたは API の移行は不要です。

## 既知の制限

- これらの制限は起動時に一度だけ読み込まれるため、変更には再起動が必要です。
- V1 の応答サイズ制限と生成タイムアウトはコード定数のままであり、
  今後のリリースで提供します。
- 完全な固定画像レシピは引き続きサーバー側の責務であり、今後のリリースで提供します。
- アニメーション画像への対応は今後のリリースで予定されています。
