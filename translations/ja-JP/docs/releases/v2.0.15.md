# v2.0.15 - 監査フォローアップ: テスト、開発環境、ドキュメント

> 開発プレリリースです。本リリースは `dev` から公開され、急速なフォローアップ変更を受ける
> 可能性があり、既定の `latest` イメージには選択されません。

## 概要

v2.0.15 はローカル負荷テスト監査で見つかった問題を修正します。必ず panic していた統合
テストは修正され、CI のスコープ付き統合ステップで実行されるようになりました。開発用
imgproxy コンテナは「全ユーザー読み取り可能」にせずに開発者アカウント所有のデータを
読めるようになり、API リファレンスとデプロイガイドは V1 動的変換の上限付き拒否動作を
説明するようになりました。ランタイム動作の変更はありません。

## 変更

### テストと CI

- `TestCompleteRollbackRestoresStagingAndCleansPersistentParts` は共有テストレシピを
  注入するようになり、nil レシピによる panic ではなくロールバック経路を実際に実行します。
- スコープ付き MySQL 統合ステップは、このテストをリースクリーンアップテストと一緒に
  実行し、CI で一度も実行されていなかったギャップを解消しました。

### 開発環境

- `backend/docker-compose.dev-deps.yml` は imgproxy コンテナにホストのグループ
  （`SUMMERAIN_DEV_GID`、既定 `1000`）を追加し、既定の「所有者/グループのみ読み取り
  可能」な権限のままでも開発者アカウント所有の原本を読み取れるようにしました。ローカルの
  V1 動的変換は、データディレクトリを全ユーザー読み取り可能にせずに動作します。

### ドキュメント

- API リファレンスとデプロイガイドは、V1 動的経路が飽和した場合に無制限に待たせず
  `1003`(503) と `Retry-After` で拒否することを説明するようになり、両翻訳も更新しました。

## 検証

- バックエンド：`SUMMERAIN_TEST_MYSQL_DSN` を設定した全量統合スイートが成功（以前 panic
  していたテストを含む）。標準スイートと CI のスコープ付き統合コマンドも成功。
- 開発環境：`docker compose config` が検証を通過。データディレクトリを所有者/グループ
  のみ読み取り可能にした状態で、V1 動的変換が 200 を返すことを確認。
- フロントエンド `npm run lint`、`tsc -b`、Vitest：22 テストファイル、164 テスト成功。
- Python requirements lock 検証と GitBook ドキュメント検証：各言語 38 ページで成功。

## インストール

開発イメージは明示的に取得する必要があります。

```bash
docker pull jaykserks/summerain:dev-v2.0.15
```

同等の正確な開発タグ：

```text
jaykserks/summerain:dev-2.0.15
```

移動タグ `dev` は最新の成功した開発ビルドも指します。本リリースは `latest`、`main`、安定版
セマンティックバージョンのエイリアスを変更しません。

v2.0.14 からのアップグレードにデータベースマイグレーションや API マイグレーションは
不要です。

## 既知の制限

- CI は依然としてスコープ付き MySQL 統合サブセットのみを実行します。全量統合スイートには
  ドキュメント記載の DSN 変数が必要です。
- 開発用グループの既定値は uid/gid `1000` を想定しています。それ以外の環境では
  `SUMMERAIN_DEV_GID` を設定してください。
- 形式拡張子のない動的変換リクエストは、設計どおり元画像を返します。
