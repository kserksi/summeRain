# v2.0.14 - Docker デプロイ構成とレシピの上書き

> 開発プレリリースです。本リリースは `dev` から公開され、急速なフォローアップ変更を受ける
> 可能性があり、既定の `latest` イメージには選択されません。

## 概要

v2.0.14 は Docker デプロイの説明を完成させます。本番ホストは Compose ファイル、`.env`、
編集可能な `config/image-recipe.json` を置いたデプロイディレクトリを用意するだけです。
レシピはイメージに焼き込まれたレシピを読み取り専用で上書きし、ファイルがない場合 Compose は
起動を拒否します。本リリースによるアプリケーションコードの変更はありません。

## 変更

### Compose

- `backend/docker-compose.yml` と `backend/docker-compose.deploy.yml` の両方が
  `create_host_path: false` を指定して `./config/image-recipe.json` を
  `/app/config/image-recipe.json` へ読み取り専用でマウントします。ファイルがない場合は
  Docker が黙ってディレクトリを作るのではなく、即座に失敗します。
- 運用担当者はデプロイ用コピーを編集して再起動するだけで、イメージを再ビルドせずに
  バリアント、上限、受け付ける形式を変更できます。
- サーバー側ポリシーファイルのデプロイ用コピーとして `backend/config/image-recipe.json`
  を追加しました。

### テスト

- `backend/deploy_config_test.go` は、両方の Compose ファイルにレシピ上書きマウントが
  あること、およびデプロイ用コピーが埋め込み既定とバイト単位で一致することを検証する
  ようになりました。

### ドキュメント

- README とデプロイガイドが、デプロイディレクトリ構成、読み取り専用のレシピ上書き、
  Compose の即時失敗、名前付きボリュームのバックアップ方法を説明します。アップグレードと
  ロールバックのコマンドはデプロイディレクトリで実行する形になり、3 言語すべてを
  更新しました。

## インストール

開発イメージは明示的に取得する必要があります。

```bash
docker pull jaykserks/summerain:dev-v2.0.14
```

同等の正確な開発タグ：

```text
jaykserks/summerain:dev-2.0.14
```

移動タグ `dev` は最新の成功した開発ビルドも指します。本リリースは `latest`、`main`、安定版
セマンティックバージョンのエイリアスを変更しません。

v2.0.13 からのアップグレードにデータベースマイグレーションや API マイグレーションは
不要です。既存環境を更新する場合は、次回起動の前に `config/image-recipe.json` を
Compose ファイルの隣（リポジトリのチェックアウトでは `backend/config/image-recipe.json`）
へ配置してください。Compose はこのファイルがないと起動を拒否します。

## 既知の制限

- 永続化された画像ファイルはホストディレクトリではなく `image_storage` 名前付きボリューム
  にあります。ドキュメントの手順でボリュームをバックアップしてください。
- レシピの変更には引き続き再起動と `recipe_version` の更新が必要です。
- リポジトリのチェックアウトを使う開発用デプロイでも、Compose ファイルの隣に同じ
  `config/image-recipe.json` のコピーが必要です。
