# v2.0.12 - ドキュメントのコンプライアンスとサードパーティ帰属

> 開発プレリリースです。本リリースは `dev` から公開され、急速なフォローアップ変更を受ける
> 可能性があり、既定の `latest` イメージには選択されません。

## 概要

v2.0.12 は英語ドキュメントを唯一の統合された正式な情報源として確立し、そのコンプライアンス
上の欠落を解消し、確定した英語から両方の翻訳を再同期します。また、ライセンス方針が求める
サードパーティ帰属ページを追加し、絵文字、構造のずれ、古いバージョン文字列に対して GitBook
検証ツールを強化します。

本リリースによるサーバー動作や API 契約の変更はありません。

## 変更

### ドキュメントの統合

- README：重複していたリクエスト図と、繰り返されていた上限値・プール数の記述を削除。機能
  表現をバージョン非依存に変更。リリースノートのリンクを GitHub Releases ページへ変更。
  アーカイブ済み設計記録にラベルを付与。技術表から帰属ページへリンク。
- USAGE：Go バージョン表記を統一（1.24+、CI は 1.26.5）。ローカルクイックスタートは
  README を参照。設定リファレンスをコードと `.env.example` に対して確認（`GOMEMLIMIT`
  が Compose 注入であることを含む）。ワーカー名をマネージャーと一致。制限表から保守者向け
  の出典列を削除。nginx のボディ上限を 20m から 64m に修正。
- API：不要になった mock フィールド対応の節を削除。エラーコード表を番号順に整列。検証
  基準の注記と文末の生成フッターを削除。
- CONTRIBUTING：Google Go Style Guide を正式な基準として明記。フロントエンドのチェックと
  ドキュメント保守の規則を追記。
- SECURITY：リポジトリ URL を統一し、開発ビルドのサポート対象に関する注記を追加。
- `backend/.env.example`：イメージ例は正確な安定版タグを維持し、本番での固定指針を
  添付。

### サードパーティの帰属

- `docs/THIRD-PARTY.md` を追加し、採用しているライブラリ、サービス、ツールチェーンを
  作者、ライセンス、リンクとともに一覧化。`NOTICE` も同様に拡充。
- `libvips`（LGPL-2.1-or-later）と Redis 8（RSALv2/SSPLv1/AGPLv3）は、未改変で独立して
  デプロイされるコンポーネントとして記載。

### 翻訳の同期

- 簡体字中国語と日本語のページを確定した英語から再同期。中国語 API ページに残っていた
  絵文字と編集上の見出しを削除。用語を統一。新しい帰属ページを翻訳。3 つのナビゲーション
  と翻訳元ハッシュを更新。

### 検証ツールの強化

- `scripts/verify-gitbook-docs.sh` は、現行ページの絵文字と古い `v2.0.0` 参照を拒否し、
  翻訳が見出し、表、コードフェンスの構造で正式な英語と一致することを要求するようになり
  ました。アーカイブ済み設計記録と日付付きリリースノートは歴史的記録として免除されます。

## 検証

- バックエンド `go build ./...`、`go vet ./...`、`go test ./...`：成功。
- フロントエンド `npm run lint`、`tsc -b`、Vite 本番ビルド：成功。
- フロントエンド Vitest：21 テストファイル、161 テスト成功。
- Python requirements lock 検証と GitBook ドキュメント検証：各言語 35 ページで成功。
- ネガティブテストにより、新しい絵文字検査と構造検査が正しく失敗することを確認。

## インストール

開発イメージは明示的に取得する必要があります。

```bash
docker pull jaykserks/summerain:dev-v2.0.12
```

同等の正確な開発タグ：

```text
jaykserks/summerain:dev-2.0.12
```

移動タグ `dev` は最新の成功した開発ビルドも指します。本リリースは `latest`、`main`、安定版
セマンティックバージョンのエイリアスを変更しません。

v2.0.11 からのアップグレードにデータベースマイグレーションや API マイグレーションは
不要です。

## 既知の制限

  のみ存在する場合があります。

- アニメーション画像への対応は今後のリリースで計画されています。
