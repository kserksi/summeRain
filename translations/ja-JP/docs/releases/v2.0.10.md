# v2.0.10 - フロントエンドがサーバーのアップロードポリシーに追従

> 開発プレリリース版。このリリースは `dev` から公開され、迅速なフォローアップ変更を受ける可能性があり、デフォルトの `latest` イメージでは選択されません。

## 概要

v2.0.10 は、ブラウザー側のアップロードパイプラインがビルド時の定数ではなく、v2.0.9 で追加した
レシピのクライアントヒントを読み取るようにします。有効な並行数とソースサイズの上限は
「サーバーヒント、デバイス能力、フロントエンドの安全上限」の最小値になり、運用担当者は
フロントエンドを再リリースせずにサーバー側からブラウザー側の負荷を下げられます。一方で
低速またはメモリの少ないデバイスは独自の下限を保ちます。ヒントを送らないサーバーでは、
従来の動作が完全に維持されます。

レシピのバージョンはフロントエンドの定数ではなくなりました。クライアントはサーバーの
バージョンをマニフェストにそのまま記載し、変更された場合は永続化済みの処理結果を
再生成します。

## 変更内容

### 有効なアップロード制限

- `client_pipeline_concurrency` と `client_active_session_concurrency` は、アップロード
  パイプラインとサーバーセッションの同時実行ゲートを決めます。どちらもフロントエンドの
  上限である 2 と 4 を超えません。
- `client_max_native_concurrency` はデバイス能力（報告されるコア数の半分、1 から 2）と
  組み合わせるため、非力なデバイスが処理能力を超えるワーカー数で動くことはありません。
- `max_source_bytes` は固定の 15 MiB 事前チェックを置き換え、ファイル追加時とプリフライト
  時の両方で適用されます。レシピ取得前に追加されたファイルもサーバーポリシーで拒否されます。
- ヒントが無い場合は同梱の既定値を使用します。これは古いサーバーが期待する動作です。
  ヒントが存在しても使用できない場合（0、負数、小数、数値以外）は上限へフォールバックし、
  該当フィールド名を含む警告トーストを 1 回表示します。設定ミスを黙って無視しません。
- フロントエンドがサーバー値や自身上限を超えて制限を引き上げることはありません。

### 動的なレシピバージョン

- ネイティブプロセッサー、WASM ワーカー、プリフライト、共有型、レシピ解析からハードコード
  された `2.0.0` を削除しました。
- パイプラインバージョンやバリアント寸法がクライアントの生成能力を超えるレシピは引き続き
  拒否し、エラーにはサーバーの `recipe_version` と `pipeline_version` が含まれます。
- サーバーのレシピバージョンが変わると、永続化済みの処理結果は破棄され再生成されます。
  アップロードキューの復旧、リース、再試行の意味は変わりません。

## インストール

開発イメージは明示的にプルする必要があります：

```bash
docker pull jaykserks/summerain:dev-v2.0.10
```

同等の正確な開発タグ：

```text
jaykserks/summerain:dev-2.0.10
```

移動する `dev` タグも最新の成功した開発ビルドを指します。`latest`、`main`、および
安定したセマンティックバージョンエイリアスはこのリリースによって変更されません。

v2.0.9 からのアップグレードにデータベース移行や API 移行は不要です。

## 既知の制限

- ヒントは引き続き助言値です。サーバーはすべてのアップロードを独立して検証し、ヒントを
  送らないサーバーでは従来のブラウザー動作が維持されます。
- ルート README は既定のパイプライン並行数のまま記載しています。ドキュメントの整備は
  デプロイメント段階で行います。
- アニメーション画像のサポートは今後のリリースで計画されています。
