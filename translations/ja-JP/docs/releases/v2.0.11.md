# v2.0.11 - クライアントクラッシュレポート

> 開発プレリリース版。このリリースは `dev` から公開され、迅速なフォローアップ変更を受ける可能性があり、デフォルトの `latest` イメージでは選択されません。

## 概要

v2.0.11 は、フロントエンドに残っていた最後のコンソール出力を、サーバーがログに記録する
上限付きの構造化クラッシュレポートに置き換えます。React のレンダリングクラッシュ、
捕捉されないエラー、未処理の Promise 拒否は、重複排除と切り詰めを経て 1 回だけ報告され、
ブラウザーのコンソールに埋もれることがなくなります。

このエンドポイントはデータベース状態を保持せず、IP 単位でレート制限され、クエリ文字列・
Cookie・トークンを決して受け取りません。フロントエンドの lint がリポジトリのコンソール
禁止を強制するようになり、従来の 3 件の例外は解消されました。

## 変更内容

### バックエンドのエンドポイント

- `POST /api/v1/public/client-errors` を追加しました。上限付きの JSON レポートを 1 件受け取り、
  リクエスト ID を含む 1 行の `[client-error]` ログを書き出します。
- レポート種別は `boundary`、`error`、`unhandledrejection` に限定されます。メッセージが空、
  または種別が未知の場合は `3000` を返します。
- フィールドはサーバー側で切り詰めます。message は 300 バイト、stack と component_stack は
  2000 バイト、source と path は 200 バイト、user agent は 200 バイトです。
- リクエスト本文は 8 KiB まで（超過時は `3002`）。1 IP あたり毎分 20 件までで、超過時は
  新しい `2091`(429) と `Retry-After: 60` を返します。Redis 障害時は従来どおり
  fail-closed です。
- ログに IP アドレス、Cookie、トークンは記録しません。

### フロントエンドのレポート

- `lib/crash-report.ts` を追加しました。サーバーと一致する切り詰め、パスのみの送信
  （クエリとフラグメントを除去するため、非公開画像のトークンは漏れません）、5 秒間の
  フィンガープリント重複排除、1 ページあたり毎分 3 件の予算を実装します。
- 起動時に一度だけインストールされる `lib/global-crash-handlers.ts` を追加し、
  React のエラーバウンダリに到達しない未捕捉エラーと未処理の Promise 拒否を報告します。
- `ErrorBoundary` は `console.error` ではなく `reportClientCrash` で報告するようになりました。
  DOM 変更エラーの自己修復リトライは変更していません。
- 画像一覧の削除フローにあった 2 つのデバッグ用 `console.error` を削除しました。
- `no-console: error` の ESLint ルールを追加しました（テストには明示的な例外あり）。
  コンソール禁止が継続的に強制されます。

## インストール

開発イメージは明示的にプルする必要があります：

```bash
docker pull jaykserks/summerain:dev-v2.0.11
```

同等の正確な開発タグ：

```text
jaykserks/summerain:dev-2.0.11
```

移動する `dev` タグも最新の成功した開発ビルドを指します。`latest`、`main`、および
安定したセマンティックバージョンエイリアスはこのリリースによって変更されません。

v2.0.10 からのアップグレードにデータベース移行や API 移行は不要です。

## 既知の制限

- レポートはサーバーログに書き出されるだけで、サーバーは集約やアラートを行いません。
- このエンドポイントは設計上公開されているため、悪意あるクライアントも呼び出せます。
  本文の上限と IP 単位のレート制限が影響を抑え、レポートに認証情報は含まれません。
- アニメーション画像のサポートは今後のリリースで計画されています。
